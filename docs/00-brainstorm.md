# 시수 밸런스 도구 — 브레인스토밍 & 기획 (v0.1)

> 학사일정(구글시트) + 기본 시간표를 넣으면
> **반별·과목별 실제 수업시수를 자동 계산**하고,
> **부족/초과·반간 편차를 경고**하며,
> **요일 교체·교시 교환 같은 보완안을 제안**하는 도구

---

## 1. 문제 정의

| 현상 | 원인 | 체감 시점 |
|---|---|---|
| 특정 과목 시수 부족 | 월요일 공휴일 집중, 특정 요일에 행사 몰림 | 학기 말, 성적 처리 |
| 특정 과목 시수 초과 | 휴일이 없는 요일에 몰린 과목 | 학기 말 |
| **같은 학년 반간 진도 차이** | 반마다 요일·교시 배치가 달라 행사/창체가 다르게 걸림 | **시험 2~3주 전** (시험범위 확정 시) |
| 창체·특별교육 교시 편중 | "7교시 안전교육" 같은 부분 교시 대체가 특정 과목만 계속 잠식 | 누적되어야 보임 |

핵심 통찰: 문제는 "총 시수"보다 **"시점별 누적 시수의 반간 편차"** 다.
시험 범위는 학년 공통인데, 진도는 반마다 다르게 나간다.

## 2. 사용자 & 시나리오

- **교무부(학사 담당)**: 학기 시작 전 학사일정을 짜면서 시뮬레이션 → 불균형을 사전에 제거
- **교과 교사**: "우리 반 국어가 3반보다 2시간 적은데 중간고사까지 몇 시간 남았지?"
- **학년부장**: 시험 3주 전 학년 전체 반×과목 편차 점검 → 보강/교환 요청

대표 시나리오
1. 2월: 학사일정 초안 시트 URL 붙여넣기 → 시간표 붙여넣기 → 1학기 시수 예측표 확인
2. "중간고사(4/28) 기준 2학년 과학: 3반 -2, 5반 +1" 경고 확인
3. 제안: "4/16(수)를 **월요일 시간표**로 운영하면 월요일 과목 편차 해소" → 시뮬레이션 → 채택
4. 학기 중 일정 변경 → 시트만 고치고 '새로고침' → 즉시 재계산

## 3. 도메인 모델

```
학기(Term)          시작일, 종료일, 목표 주수(예: 17주)
기본 시간표(Grid)    반 × 요일 × 교시 → 과목 (+교사)
편제 시수(Target)    학년 × 과목 → 학기 목표 시수 (또는 주당시수 × 주수)
일정(Event)          날짜/기간, 유형, 적용범위(전교/학년/반), 적용교시, 대체내용
규칙(Rule)           유형별 시수 처리 방식 (아래 표)
체크포인트            중간/기말고사 등 "여기까지의 누적 시수"를 보는 기준일
```

### 일정 유형 → 시수 처리 규칙 (학교마다 설정 가능)

| 유형 | 예시 | 처리 |
|---|---|---|
| 휴업 | 공휴일, 재량휴업, 방학, 개교기념일 | 해당일 전 교시 삭제 |
| 전일 행사 | 수련회, 체육대회, 현장체험학습, 축제 | 해당 범위 전 교시 → 창체로 이동 |
| 부분 교시 대체 | "5~6교시 창체", "7교시 성교육" | 지정 교시만 창체/특별교육으로 이동 |
| 시험 | 중간·기말 지필평가 | 설정: 교과 시수 인정 / 불인정 / 시험교시만 대체 |
| 단축 수업 | 방학식, 시험 전날 | 지정 교시 이후 삭제 |
| **요일 교체** | "수요일 → 월요일 시간표 운영" | 해당일 시간표를 다른 요일로 치환 (보완 수단) |
| 개별 교환 | 3반 4/10 3교시 국어↔수학 | 반 단위 교시 교환 (보완 수단) |

## 4. 계산 엔진

```
for 반 in 반목록:
  for 날짜 in 학기 수업일:
    요일시간표 = 요일교체 규칙 적용(날짜)
    for 교시 in 요일시간표:
      이벤트 = 해당 날짜·반·교시에 걸린 일정 (우선순위: 휴업 > 전일 > 부분 > 교환)
      → 과목 시수 +1  또는  창체/특별교육 +1  또는  삭제
      → 누적 시계열 기록 (날짜별)
```

산출물
- **반 × 과목 매트릭스**: 계획 시수 / 목표 / 차이(%)
- **체크포인트별 누적**: 시험일 기준 반간 편차 (max − min)
- **요일별 손실 분석**: "월요일 손실 5일" → 원인 설명
- **일정별 영향도**: 이 행사 하나가 어느 과목을 몇 시간 깎았는지

모두 순수 함수 → 입력이 바뀌면 즉시 재계산, 단위 테스트로 검증.

## 5. 경고 & 보완 제안

### 경고 등급
- 🔴 **위험**: 목표 대비 −5% 초과 부족, 또는 시험 체크포인트 반간 편차 ≥ 2시간
- 🟡 **주의**: −2~5% 부족, 편차 1시간
- 🔵 **초과**: 목표 대비 +5% 초과 (다른 과목에 양보 가능한 여유)

### 보완 제안 (우선순위순)
1. **요일 교체 제안** — 손실이 큰 요일의 시간표를 여유 있는 날에 운영.
   후보 날짜 전체를 탐색해 "총 편차 감소량"이 큰 순으로 추천
2. **창체/특별교육 교시 재배치** — "7교시 안전교육"을 초과 과목이 걸린 교시로 이동
3. **반별 교시 교환** — 시험 전 특정 반의 A↔B 과목 교환으로 반간 편차 해소
4. **보강 필요 목록** — 위 방법으로도 해결 안 되는 잔여 부족분

각 제안은 **"적용 전 → 적용 후" 미리보기**(What‑if)와 부작용(다른 과목 영향)을 함께 표시.
알고리즘: 1차는 탐욕(greedy) 탐색 + 점수함수 `Σ|편차| + λ·체크포인트 반간편차`, 필요 시 고도화.

## 6. 입력 방식 (가장 중요한 UX)

교사는 "양식 맞추기"를 싫어한다 → **있는 시트를 그대로 읽는다**.

1. **학사일정**: 구글시트 URL(웹에 게시 CSV) / 복사-붙여넣기 / xlsx 업로드
   - 열 매핑 자동 추정(날짜·요일·행사명·비고)
   - 행사명 **키워드 자동 분류**: "재량휴업", "체육대회", "5-6교시", "창체", "지필" 등 → 유형·교시 추출
   - 사용자는 표에서 **확인/수정만** (자동 분류 신뢰도 낮은 항목 하이라이트)
2. **시간표**: 시간표 프로그램/엑셀에서 표 복사-붙여넣기 → 반×요일×교시 그리드 인식
3. **편제 시수**: 주당시수 자동 추정(시간표에서 계산) + 필요 시 수정

## 7. UI/UX 콘셉트

톤: **차분한 뉴트럴 + 한 가지 포인트 컬러**, Pretendard, 라이트/다크, 데이터 우선의 여백 있는 레이아웃
(Linear·Notion·Vercel 대시보드 계열의 담백함)

화면 구성
| 화면 | 핵심 요소 |
|---|---|
| **온보딩 마법사** | ① 학기 ② 시간표 ③ 학사일정 ④ 자동분류 확인 — 4단계, 진행바 |
| **대시보드** | KPI 카드(수업일수·위험 과목 수·최대 반간 편차·다음 시험 D‑day) + 반×과목 **히트맵**(발산형 색상) |
| **캘린더** | 시트 데이터를 달력으로 역변환해 시각화, 날짜 클릭 시 "이 날 빠지는 과목" |
| **반 상세** | 과목별 누적 시수 라인차트 vs 이상선, 시험일 세로선 |
| **시험 대비** | 체크포인트 선택 → 과목별 반간 막대 비교, 편차 순 정렬 |
| **제안** | 카드 리스트, 각 카드에 효과(−편차) 배지 + "시뮬레이션" 토글 → 전체 화면이 즉시 반영 |

인터랙션 원칙
- 모든 숫자는 **클릭하면 근거**(어떤 날짜·일정 때문에 빠졌는지)를 보여준다
- What‑if 모드: 원본을 건드리지 않고 가상 적용 → 비교 → 채택 시에만 반영
- 결과 내보내기: 구글시트/엑셀, 인쇄용 1장 리포트(학년부 회의용)

## 8. 기술 방향 (제안)

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. 독립 웹앱 (추천)** React + TypeScript + Vite, 서버 없이 브라우저에서 계산, GitHub Pages 배포 | 세련된 UI 자유도, 빠름, 설치 불필요, 개인정보 서버 전송 없음 | 시트 연동은 CSV 게시/붙여넣기 방식 |
| B. 구글시트 부가기능 (Apps Script 사이드바) | 시트 안에서 바로 사용 | UI 제약 큼, 느림, 디자인 한계 |
| C. 하이브리드 | A의 UI + B로 결과를 시트에 되쓰기 | 개발량 증가 (2단계로 미룰 수 있음) |

계산 엔진은 UI와 분리된 순수 TS 모듈 → 나중에 Apps Script로도 이식 가능.

## 11. 확정이 필요한 질문
1. 도구 형태: 독립 웹앱 / 시트 부가기능 / 하이브리드
2. 현재 시간표 관리 방식 (시간표 프로그램, 엑셀, 구글시트 …)
3. 학사일정 시트 구조 (한 행=하루 / 한 행=행사 / 시트 안 달력 그리드)
4. 학교급·규모 (학년 수, 학년별 반 수, 하루 최대 교시, 수업 단위 45/50분)
5. 시험 교시 시수 인정 방식, 창체의 세부 영역(자율/동아리/진로) 구분 필요 여부
6. 실제(익명화된) 학사일정·시간표 샘플 제공 가능 여부 → 자동분류 정확도의 핵심
